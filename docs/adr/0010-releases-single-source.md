# 0010. Версии и заметки — один источник данных, тест против расхождения

## Контекст

Выкладок на сайт было семь (13.11–20.11), версий и журнала не было, `package.json` стоял на 1.0.0. Пользователь просит журнал изменений и заметки «для каждой и каждой выкладки», и номер версии в игре.

## Решение

Записи о выкладках — чистые данные в `src/core/releases.js`. `CHANGELOG.md` и `RELEASE_NOTES.md` порождаются из них командой `npm run notes`, а игра читает те же данные для версии и окна «Что нового». Тест падает, если версия `package.json` (и `package-lock.json`) не совпадает с последней записью или файлы отстали. Нумерация: минорная — волна, патч — исправления; первая выкладка — 1.0.0, потому что так стояло в `package.json`. Записи задним числом сделаны по истории git и журналам волн. Теги и выпуски на GitHub не создаются.

## Почему

- Вести файлы вручную отвергнуто: игра и файлы разойдутся, и никто не заметит.
- Читать заметки игры из Markdown отвергнуто: потребовался бы разбор Markdown в бандле и отдельный перевод; данные с двумя языками проще.
- Теги и выпуски на GitHub отвергнуты: это публикация, а любое изменение публичного сайта — только с отдельного «да» пользователя.
- Тест идёт в `npm test`, который гоняет и выкладка на GitHub, поэтому выкладка без записи не уйдёт.

## Последствия

- Каждая следующая выкладка вынуждена сначала получить запись и версию; исправление в одну строку тоже требует их.
- Первые семь записей восстановлены задним числом, их точность зависит от истории git; поле «известные проблемы» берётся из `PROGRESS.md` и проверяется тестом.
- Названия карт и оружия в заметках проверяются на совпадение с игрой, так что переименование ломает тест.
