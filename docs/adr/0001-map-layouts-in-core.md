# 0001. Раскладки карт — данные и генератор в чистом ядре

## Контекст

Единственная карта, «Квартал», собрана вручную в одном большом построителе мира с жёсткими координатами. Девять новых карт нужно проверять на проходимость, а мир под Node не запускается.

## Решение

Каждая новая карта — раскладка: чистые данные (здания с проёмами, укрытия, предметы, дороги, петли ездоков, точки появления, старт, свет). Её порождает генератор в `src/core` по идентификатору карты, без three и DOM. Игровой слой только превращает раскладку в меши.

## Почему

- Ручная постройка по образцу «Квартала» отвергнута: порядок вызовов и сквозной расход `world.rng` делают результат неуправляемым, а проверить зазоры петель, достижимость точек появления и пересечения без браузера нельзя.
- Хранить раскладки готовыми файлами данных отвергнуто: девять карт по 90 × 90 м вручную не написать и не поддерживать, а детерминированный генератор с зерном на карту даёт то же самое.
- Выгода выбранного: тесты `npm test` ловят «точка появления внутри стены» и «петля задевает стену» до запуска игры.

## Последствия

- Каждая карта обязана пройти общий набор тестов: детерминизм, не менее 16 достижимых точек появления, петля с зазором не менее 0.8 м, не менее 6 зданий с дверями.
- Раскладка — общий кэшированный объект: ни мир, ни магазин не имеют права её менять.
- Первое построение раскладки стоит 70–120 мс; схемы для магазина приходится считать один раз и держать.
- Правка генератора меняет карту целиком: «каждая карта одна и та же от игры к игре» держится только пока зерно и порядок вызовов не тронуты.
